# Reproduce the second-aligner investigation

Run from this project directory in PowerShell, using the existing local assets.
These are diagnostic runs, not the main study. No command calls a hosted inference
API. Run GPU jobs sequentially and check free memory first. The original audio and
primary exports are inputs, never overwritten. New code/configuration requires a
fresh run name where exposed; do not edit a completed manifest to force resumption.

## Environments and pinned assets

- Main: `.venv/Scripts/python.exe`, portable CPython 3.12.16, torch 2.8.0+cu128.
  `requirements-exploration-lock.txt` adds Charsiu's dependencies to the original
  version snapshot. The old `requirements-lock.txt` is preserved.
- MFA 2: `.runtime/mfa/`, original tested environment and acoustic model.
- MFA 3: `.runtime/mfa3/`, Python 3.10.22, MFA 3.0.7, Kalpy 0.6.4 CPU, Kaldi
  5.5.1112 CPU, OpenFst 1.8.3, Pynini 2.1.6. Native package URLs, builds and hashes
  are in `runs/model-locks/mfa3-runtime.json`; Python versions are in
  `requirements-mfa3-lock.txt`. The Python snapshot is not a pip-only installation
  recipe: native Kalpy/Pynini/Kaldi came from Conda. Optional long test-file paths
  prevented a clean Conda transaction, so pinned wheels completed the environment.
- VAD: `.venv-vad/Scripts/python.exe`, unchanged independent ONNX Runtime/NumPy
  environment recorded in `requirements-vad-lock.txt`. Silero needs no new package.

Model/code revisions and individual file SHA256s are in `runs/model-locks/`:
`charsiu_zh.json`, `charsiu-code.json`, `charsiu-tokenizer.json`, `g2pm.json`,
`mfa3_zh.json`, `silero_vad.json`, and the pre-existing Kokoro/MFA locks. Charsiu
code was loaded from the pinned local source; its checkpoint is never executed as
remote code. The installed Transformers loader reports no missing/unexpected/
mismatched weights. Preserve local weight files; Charsiu checkpoint metadata does
not specify an explicit redistribution license. Included license texts are under
`docs/licenses/`.

MFA's two automatic G2P additions are in `runs/mfa3-g2p/supplement.dict`; inputs
are `data/scripts/mfa3-oov.txt`. No manual pronunciation or boundary annotation.
`config/mfa3-alignment.yaml` uses already tokenized transcripts and disables
adaptation/fine-tuning. `language: unknown` suppresses automatic retokenization,
not the Mandarin acoustic model.

The first three use GPU and checkpoint each clip/intervention. They preserve token

`signal-origin-v1/` separates native output, resampling and approximate PCM16 effects.
`pcm-audit-v1/` verifies the actual libsndfile conversion against all 40 historical
MFA input copies; the floor approximation differs by at most one LSB.
`decoder-localization-v1/` separates generator style scale/shift from the style
of pre-generator features, with native baseline identity checks.
`ac-rms-v1/` contains the 480-case background challenge; `detrended-rms-v1/` adds
576 gap challenges and 252 non-silent probes per method. Native STFT bin components
are not brick-wall frequency filters.

```powershell

& '.venv\Scripts\python.exe' -X utf8 -m timing.alignment_stability charsiu

& '.venv\Scripts\python.exe' -X utf8 -m timing.mfa3_run --source intact-stability-v1 --run mfa3-stability-v1

& '.venv\Scripts\python.exe' -X utf8 -m timing.mfa_variants --baseline mfa-stability-v1 --run mfa-stability-d0-v1 --dither-zero
& '.venv\Scripts\python.exe' -X utf8 -m timing.onset_ablation
& '.venv\Scripts\python.exe' -X utf8 -m timing.mfa_ablation prepare
& '.venv\Scripts\python.exe' -X utf8 -m timing.mfa_run --source onset-ablation-audio-v1 --run mfa-ablation-v1 --limit 98
& '.venv\Scripts\python.exe' -X utf8 -m timing.mfa3_run --source onset-ablation-audio-v1 --run mfa3-ablation-v1
& '.venv\Scripts\python.exe' -X utf8 -m timing.mfa_ablation evaluate
& '.venv\Scripts\python.exe' -X utf8 -m timing.repeatability_audit mfa2
& '.venv\Scripts\python.exe' -X utf8 -m timing.repeatability_audit mfa3
& '.venv\Scripts\python.exe' -X utf8 -m timing.repeatability_audit evaluate
```

Padding tests retain the speech samples. Gain tests include MFA's PCM16 copy and
its dither, so they are pipeline sensitivity tests. The ablation operates after
resampling and writes exact zeros. The original transcript is retained despite
removed speech: predictions inside zeros reveal context/duration assumptions,
not an independent annotation of natural speech. Global feature normalization
turns zeros into a constant, with no acoustic variation inside them.

## Streaming contrast and held-out fixtures

```powershell
& '.venv-vad\Scripts\python.exe' -X utf8 -m timing.silero_probe
& '.venv\Scripts\python.exe' -X utf8 -m timing.holdout_fixtures
& '.venv-vad\Scripts\python.exe' -X utf8 -m timing.silero_phase
& '.venv\Scripts\python.exe' -X utf8 -m timing.mfa_run --source pause-holdout-v1 --run mfa-holdout-v1 --limit 288
& '.venv\Scripts\python.exe' -X utf8 -m timing.mfa3_run --source pause-holdout-v1 --run mfa3-holdout-v1
& '.venv\Scripts\python.exe' -X utf8 -m timing.charsiu_holdout
& '.venv\Scripts\python.exe' -X utf8 -m timing.holdout_analysis
& '.venv\Scripts\python.exe' -X utf8 -m timing.paired_measurement_sensitivity
& '.venv\Scripts\python.exe' -X utf8 -m timing.quiet_selector_v2
```

The held-out Charsiu run uses CPU with four threads to avoid competing for a busy
GPU. It resumes per clip; `--limit 1` is an execution-only smoke test and does not
change the 288-case scientific configuration. Its default CPU run is reported
separately from earlier CUDA runs. `silero-phase-v1/` records an early missing-import
failure before any inference; corrected code writes `silero-phase-v2/`. No threshold
or timestamp offset was selected using natural alignment agreement.

`holdout-analysis-v2/` adds the already computed 0.3 Silero sensitivity to the
combined table. Version 1 omitted that column from its aggregation; every other
method's values are unchanged. The original complete 0.3/0.5/0.7 outputs are in
`silero-phase-v2/` and no inference was repeated for this reporting correction.

The new 288 fixtures use scripts 002/004/005/007/008/010, absent from the old 96.
Each method gets the same known edit and broad search bracket. Original 0.3/0.5/0.7
thresholds remain visible; the four-phase average is a separately named method.
`paired-measurement-sensitivity-v1/` reports changes in paired contrasts between
estimators, with all flags retained. It is not a test of comedic timing.
`quiet-selector-v2/` tests qualification-before-censoring. It fixes four
fixture-method entries across two clips, leaves all 40 natural estimates unchanged,
and retains the old tables as the originally run versions.

## Reports and verification

```powershell
& '.venv\Scripts\python.exe' -X utf8 -m timing.second_aligner_report
& '.venv\Scripts\python.exe' -X utf8 -m timing.exploration_provenance
& '.venv\Scripts\python.exe' -X utf8 -m unittest discover -s tests -v
& '.venv\Scripts\python.exe' -X utf8 -m timing.exploration_verify
```

The report command generates the Markdown findings, local HTML/audio page, 40
per-clip figures, three aggregate figures, the original Charsiu fixture table, and
SHA256 provenance. `--skip-plots` updates numerical prose without rerendering
unchanged figures. `--draft` is only for the interim report before the held-out
Charsiu run completes. `exploration_provenance` records versions and retained
download evidence; it does not install anything. No server is needed for the HTML.

All results are exploratory. Original metric export and all original 34 flags
remain unchanged. Gate 1 is not implicitly approved by running these commands.
